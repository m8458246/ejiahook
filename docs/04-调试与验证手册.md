# 调试与验证手册

## 1. logcat：模块自己的日志

所有 hook 日志统一用 tag `EjiaHook`，并且会经过 LSPosed 转发，前缀里带模块信息：

```bash
# 只看模块日志
logcat -s EjiaHook:V

# 看模块加载情况（框架打的）
logcat -s LSPosedFramework:V | grep 模块加载

# 只看目标进程
pid=$(pidof com.dcits.ehome)
logcat -d --pid=$pid | grep EjiaHook
```

正常启动应该看到这几行（顺序固定）：

```
模块加载: process=com.dcits.ehome framework=LSPosed api=102 remote=true
ejia 就绪，开始安装 hook
定位 hook 安装完成（writeBack=true）
设备标识 hook 安装完成，共 14 个
调试 hook: EncapPluginResult#sendJsonObjectResult
调试 hook: Geolocation#execute
调试 hook: DsBridgeWebViewActivity#hanndleLocationData
调试 hook: H5 定位 JSON
root 检测 hook 安装完成，共 6 个
系统定位 hook 安装完成，共 2 个
配置来源: debug-file /sdcard/Download/ejiahook/config.json
```

**排查顺序**：先看有没有"模块加载"，再看有没有"安装完成"，最后看"配置来源"。
少哪一行，问题就出在哪一段。

## 2. 配置来源怎么看

`配置来源:` 后面跟的字符串说明配置从哪读的：

| 值 | 含义 |
|---|---|
| `debug-file /sdcard/Download/ejiahook/config.json` | 正常（推荐） |
| `debug-file /sdcard/Download/ejiahook (3).json` | 读到了历史遗留文件，建议清理 |
| `remote-prefs(N)` | 走了框架接口，N 是条目数，0 表示空 |
| `provider` | 走了 ContentProvider |

如果日志里完全没有这一行，说明配置读取卡住了（文件不存在 + 其它通道都失败）。

## 3. 验证「上报的就是日志里的值」

这是这个项目最核心的一条验证，步骤：

1. `config.json` 里把 `"debug"` 改成 `true`
2. 重启目标应用，进一次考勤页
3. 抓两样东西对比：

```bash
# a) H5 实际收到的定位 JSON
logcat -d | grep "H5 定位 JSON"

# b) 定位日志文件
head -1 /sdcard/Download/ejiahook/location.log
```

期望两边数字**逐字一致**：

```
H5 定位 JSON = {"address":"云南省昆明市五华区教场东路",
              "latitude":25.064534767894727,
              "longitude":102.70296753156354}

11-11 11:22:37  25.064534767894727,102.70296753156354  偏移 3.5m
```

4. 验证完把 `"debug"` 改回 `false`（那个 hook 会在每次 JSON 序列化时做字符串扫描，没必要常开）

## 4. 验证漂移真的在变

连续进两次考勤页（或等待两次定位回调），对比日志前两行：

```
11-11 11:22:37  25.064534767894727,102.70296753156354  偏移 3.5m
11-11 11:14:37  25.064568,102.702976  偏移 1.7m
```

- 坐标不同、偏移不同 → 正常
- 坐标完全相同、偏移也相同 → 漂移没生效（检查 `radius` 是否为 0，或配置缓存没刷新）

注意：`偏移` 是相对配置目标点算的距离，不是两次之间的差。半径 10 米时，偏移应落在 0~10 米。

## 5. 验证 hook 是否真的改了值

`debug=true` 时，每次替换都会打一行：

```
定位替换 K: 原值=25.064565 -> 25.064534,102.702967 (偏移 3.5m)
```

- `原值` 是百度算出来的真实值
- 箭头后面是替换后的值
- 第二次读同一对象时 `原值` 会变成我们写回去的值，这是正常的（幂等写回）

## 6. 目标应用日志里的有用线索

| 日志 | 含义 |
|---|---|
| `CCGeolocation initialize` | Cordova 定位插件初始化 |
| `D FPaaS : headers: {...}` | 发给服务端的请求头（`latitude`/`longitude` 恒为空） |
| `H5 收到 code=0 body=...` | 原生回给 H5 的所有插件结果（需要 debug=true） |

## 7. 常见异常对照

| 现象 | 可能原因 |
|---|---|
| 没有"模块加载" | 模块没启用 / 作用域没勾 / APK 被卸载重装后状态丢失 |
| 有"模块加载"但没有"安装完成" | `onPackageReady` 里抛异常，看紧跟的 ERROR 日志 |
| 有"安装完成"但没有"配置来源" | 配置文件不存在，且其它通道也失败 |
| 配置来源是旧文件名 | 有历史遗留文件，删掉 `Download/ejiahook*.json` |
| 日志有值但 App 行为没变 | 检查是否 `enabled=false`，或 App 用了别的定位路径 |
| 打卡页显示距离但地址没变 | 正常，地址和坐标是两套字段 |

## 8. 调试工具速查

```bash
# 看模块是否被 LSPosed 识别
lspctl status

# 看目标进程
pidof com.dcits.ehome

# 看当前前台 Activity（判断页面是否切换成功）
dumpsys activity activities | grep -m1 topResumedActivity

# 直接调用模块的 ContentProvider（兜底通道验证）
content call --uri content://com.cycy.ejiahook.config --method get

# 读配置 / 日志
cat /sdcard/Download/ejiahook/config.json
head -5 /sdcard/Download/ejiahook/location.log

# 重启目标应用
am force-stop com.dcits.ehome
am start -n com.dcits.ehome/.activity.SplashScreenActivity
```

## 9. 盲操作技巧

目标 App 的 WebView 截图全黑、无障碍树为空时，可以按已知坐标盲点：

```bash
input tap 702 402      # 首页"考勤"入口（这台设备上的坐标）
input keyevent BACK    # 返回
```

前提是坐标是用户给的、且点击后能从日志/Activity 变化确认生效。
**不要在不确定坐标的地方盲点**，尤其是"提交/打卡"这类按钮。
