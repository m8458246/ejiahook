# 维护与升级

## 1. 代码在哪、怎么出包

```
仓库：https://github.com/m8458246/ejiahook
分支：main
产物：https://github.com/m8458246/ejiahook/releases/download/latest/app-release.apk
```

推送到 `main` 会自动跑 GitHub Actions：

1. `./gradlew :app:assembleDebug :app:assembleRelease`
2. 上传 artifact
3. 发布到 `latest` release

构建失败时会把 `build.log` 推到 `ci-logs` 分支（artifact 和 run 日志都需要登录才能看，
这个分支是为了能在外部直接读日志）。

下载后安装：

```bash
pm install -r app-release.apk
```

**不要卸载重装**——签名已经固定，覆盖安装即可；卸载会清掉 LSPosed 的启用状态和作用域。

## 2. 本地怎么快速做类型检查

完整构建依赖 Android SDK，本地不一定有。但可以做纯 javac 类型检查：

```bash
# 准备一次
curl -sL -o platform-35.zip https://dl.google.com/android/repository/platform-35_r02.zip
unzip -o platform-35.zip "*/android.jar" -d p
curl -sL -o api.aar https://repo1.maven.org/maven2/io/github/libxposed/api/102.0.0/api-102.0.0.aar
unzip -o api.aar classes.jar -d apijar

# 每次改完代码
javac -nowarn -proc:none --release 17 \
  -cp "p/android-35/android.jar:apijar/classes.jar" \
  -d out $(find app/src/main/java -name "*.java")
```

（`R.java` 是构建时生成的，本地检查需要自己写个 stub，否则会报 `package R does not exist`。）

## 3. 目标 App 更新后要检查什么

本项目的方法名是从当前 APK 里读出来的，App 一更新（尤其是重新混淆）就可能失配。
失效时**不会崩**，只会在日志里留警告：

| 日志 | 含义 | 处理 |
|---|---|---|
| `BDLocation.K()/Q() 签名不符（APK 可能已更新）` | 经纬度 getter 变了 | 重新对映射 |
| `BDLocation.d() 未找到，地址覆盖不可用` | 地址 getter 变了 | 同上 |
| `设备标识 hook 安装完成，共 0 个` | TelephonyManager 相关全没挂上 | 一般不会，留意 |
| `系统定位 hook 安装完成，共 0 个` | 框架类 hook 失败 | 看是否被其它模块拦截 |

重新对映射的步骤见 `05-逆向速查.md` 第 3 节，核心是：

1. 找 `BDLocation` 的调用点，看它调了哪几个 getter
2. 看 getter 返回哪个字段、哪个 setter 写同一个字段
3. 从 SDK 解析 JSON 的地方确认地址各段语义

改完更新 `LocationHooks.install()` 里的方法名常量即可。

## 4. 加一个新的 hook 点

模板：

```java
try {
    Method m = cls.getDeclaredMethod("方法名", 参数类型...);
    m.setAccessible(true);
    module.hook(m).intercept(chain -> {
        Config c = Config.get();
        if (!c.enabled) return chain.proceed();      // 没开就原样透传
        Object result = chain.proceed();
        // ... 处理
        return result;
    });
} catch (Throwable t) {
    module.log(Log.WARN, TAG, "hook xxx 失败: " + t);   // 失败只记日志，不抛
}
```

三条纪律：

- 所有 hook 都要 `try/catch`，失败降级而不是让目标应用崩
- 拿 `chain.getThisObject()` 先判空（静态方法为 null）
- 改动类 hook 要能被配置关掉，方便出问题时快速回退

## 7. 出问题时的回退顺序

1. App 里取消勾选「同时伪造系统定位」→ 只保留 BDLocation 那层
2. App 里取消勾选「启用定位伪造」→ 完全不改定位
3. 取消勾选「启用设备标识覆盖」→ 设备标识恢复真实值
4. 还不行就在 LSPosed 里停用模块

每一步都不需要卸载，改完保存即可。
