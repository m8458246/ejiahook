# 逆向速查（APK 分析）

工具：`apktool`（资源 + smali）、`jadx`（Java 源码）、`unzip`、`grep`。

## 1. 拿到 APK 先做三件事

```bash
# 1) 看有没有加固/多 dex/so
unzip -l app.apk | grep -E "classes.*dex|lib/"

# 2) 解 manifest + 资源（-s 跳过 dex 反编译，快）
apktool d -f -s -o out app.apk

# 3) 反编译 Java（-j 控制并发，--no-res 跳过资源）
jadx -d src --no-res -j 4 app.apk
```

`AndroidManifest.xml` 里优先看：

- `package` / `targetSdkVersion`（决定包可见性、存储权限行为）
- `<uses-permission>`（推断功能）
- `<meta-data>`（第三方 SDK 的 key，比如百度 `com.baidu.lbsapi.API_KEY`）
- `android:process`（多进程会影响 hook 安装次数）

## 2. 快速判断用了什么 SDK

直接对 dex 做字符串搜索，比翻源码快得多：

```bash
# 定位类 SDK
for k in "com/amap/api/location" "com/baidu/location" "com/tencent/map"; do
    printf "%-28s " "$k"; grep -ac "$k" classes.dex classes2.dex
done

# 关键 API
for k in getDeviceId getImei getSubscriberId ANDROID_ID getSerial isFromMockProvider; do
    printf "%-18s " "$k"; grep -ac "$k" classes.dex
done
```

命中数为 0 不代表没用——可能被混淆了，要结合 so 文件名判断
（`liblocSDK8b.so` = 百度定位，`libBaiduMapSDK_*` = 百度地图）。

## 3. 混淆类的方法名怎么反推

以百度 `BDLocation` 为例，需求是"找到纬度和经度的 getter"。

### 第一步：找调用点

```bash
grep -rn "bDLocation\." src/ | head
```

输出里看到：

```java
double dK = bDLocation.K();
double dQ = bDLocation.Q();
String strI = bDLocation.i();
String strD = bDLocation.d();
```

再看字段用途（`jSONObject.put("city", strI)`、`put("address", strD)`），就知道
`i()` = 城市、`d()` = 地址。`K()`/`Q()` 被放进 `latitude`/`longitude`，于是确定是经纬度。

### 第二步：确认字段与 setter

```bash
grep -n "public double K()" -A2 src/com/baidu/location/BDLocation.java
# public double K() { return this.e2; }

grep -n "this.e2 = " src/com/baidu/location/BDLocation.java
# 构造函数里初始化 Double.MIN_VALUE；j1(double) 里赋值
```

于是：`K()` 读字段 `e2`，`j1(double)` 写字段 `e2`；`Q()` 读 `f2`，`p1(double)` 写 `f2`。

### 第三步：地址各段的语义

地址字段存在内部类 `a` 里，光看 getter 不知道谁是谁。去 SDK 解析服务端 JSON 的代码里找：

```java
String string18 = jSONObject.has("province") ? jSONObject.getString("province") : str3;
string2 = jSONObject.has("district") ? ... ;
String string = jSONObject.has("street") ? ... ;
...
new a.C0037a().p(string3).q(string4).s(str12).n(str10).o(string6)
        .r(string2).t(string).u(str6).l(str11).v(string5).m();
```

配合 `str12 = string18`（province）、`str10 = string17`（city），再对照 getter 读的字段：

| getter | 字段 | 语义 |
|---|---|---|
| `c0()` | f5107c | province（省） |
| `i()` | f5108d | city（市） |
| `r()` | f5110f | district（区） |
| `k0()` | f5111g | street（街道） |
| `d()` | f5113i | address（完整地址） |

**关键**：混淆名不可怕，语义可以从"解析源"和"消费点"两头夹出来。

## 4. 找回调注册点

想 hook 某个回调，先找它在哪里被注册：

```bash
grep -rn "registerLocationListener\|\.y0(" src/com/dcits | head
```

如果发现注册方法本身也被混淆（`LocationClient.y0(listener)`），就 hook 它的调用点或者直接
hook 数据对象，比猜测接口实现更稳。

## 5. 判断有没有检测逻辑

```bash
# root / hook / 调试器 / 模拟器
grep -rn --include=*.java -E "isRoot|checkRootPermission|isDebuggerConnected|isFromMockProvider|Xposed|frida" src/
```

注意误报：`android/support/v4/util/PatternsCompat.java` 里有超长的域名正则，
包含 `exposed`、`android` 等词，会让 grep 命中一大坨。加 `--include` 限定目录，
或者排除 `android/support`。

so 里的检测看字符串：

```bash
grep -aoE "(xposed|magisk|frida|ptrace|/proc/self/maps|TracerPid)" lib/arm64-v8a/libxxx.so | sort | uniq -c
```

## 6. 判断热更新能力

```bash
# X5 / TBS 内核
grep -ac "TbsDownloader\|QbSdk" classes2.dex

# Cordova 热更新（chcp）
grep -ac "chcp" classes.dex

# H5 资源包
grep -rn "h5resources" src/ | head
```

对混合应用来说，**H5 是远端的**，前端逻辑随时能变，APK 里能看到的只是"桥"有哪些能力。

## 7. 常用命令备忘

```bash
# 在 dex 里找 URL
grep -aoE "https?://[a-zA-Z0-9._/?=&%-]+" classes.dex | cut -d: -f2- | sort -u

# 看 so 清单
ls out/lib/arm64-v8a/

# 看某个类被谁引用
grep -rln "BaiduMapUtils" src/

# 反编译单个 dex（大 APK 拆开更快）
jadx -d src2 --no-res classes2.dex

# 看 APK 里的 META-INF（判断是不是 Xposed 模块）
unzip -l app.apk | grep META-INF/xposed
```

## 8. 分析大 APK 的省时技巧

- 先用 `grep -ac` 在 dex 上做关键词命中统计，定位到"有没有"，再决定要不要全量反编译
- `jadx` 一次只反一个 dex，比整包快很多
- 目标代码通常在 `com/<公司域>` 下，第三方 SDK 目录可以先跳过
- 实在找不到入口时，从 `AndroidManifest.xml` 的 `<activity>` 反推（`SplashScreenActivity`
  → `MainActivity` → 具体功能页）
